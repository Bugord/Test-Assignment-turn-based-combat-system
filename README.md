# Пошаговая боевая система

Прототип пошагового боя на Unity 6.6

## Как запустить

Открыть проект в Unity 6000.6.6f1. Пакеты (UniTask, VContainer, UniState, UIKit) подключены через git и скачаются сами при открытии

Play можно жать из любой сцены, редакторский скрипт `BootScenePlayMode` всегда запускает игру с `Boot Scene`. Дальше в меню нажать старт боя

## Что сделал

Основная часть сделана полностью:

- Две команды по 4 слота. Фронтовым считается ближайший к противнику живой персонаж, сами персонажи никуда не двигаются
- У персонажей есть HP, Speed, Attack и Defense. Шанс попадания считаю как `base + (Attack - Defense) * perPoint` и ограничиваю в пределах `[min, max]`, все коэффициенты лежат в `DefaultBattle.asset`
- Ближняя атака работает только с фронтовой позиции и только по фронтовому. Дальняя бьёт по любому, но с фронтовой позиции получает штраф к Attack. Лечение без броска и не выше максимума. Пропуск хода есть у всех
- Раунды с очередью инициативы по Speed. Если персонаж умер до своего хода, он выпадает из очереди. Активный персонаж и очередь показываются в UI
- Противниками управляет простой AI, правила у него те же, что и у игрока
- Действия идут строго по очереди: замах, попадание или промах, возврат на место, и только потом следующий ход. Повторные клики во время хода ничего не делают
- Когда у одной из сторон никого не осталось, бой останавливается и показывается попап с победителем

Iteration 2 (пауза и перезапуск) сделал. В паузе можно продолжить, перезапустить бой или выйти в меню. Прервать бой можно в любой момент, в том числе посреди анимации. Все асинхронные операции отменяются через `CancellationToken`, а при перезапуске бой собирается заново

Iteration 3 (data-driven) тоже сделал, на ScriptableObject в `Assets/Configs/Battle`. Там лежат способности, персонажи, состав команд и настройки шанса попадания. Способность описывается набором параметров: кого можно выбрать целью, область действия (одна цель, соседи или все), эффект, сила, нужен ли бросок, нужна ли фронтовая позиция и штраф. Поэтому массовое лечение или удар по соседям делается без нового кода. Набор способностей у персонажа любой, например у Hybrid есть и ближняя, и дальняя атака

## Технические решения

Логику боя вынес в отдельную сборку `Combat`. Это обычные C# классы без MonoBehaviour, они не знают ни про UI, ни про визуал. `Battle` сам ведёт очередь и проверяет каждое решение перед применением, так что сломать правила не получится ни из UI, ни из AI

Весь бой крутится в одном цикле в `BattleDriver`. Сначала показывается начало хода, потом контроллер принимает решение, оно применяется в `Battle`, и цикл ждёт, пока презентация всё проиграет. Игрок и AI реализуют один интерфейс `IUnitController`, поэтому циклу всё равно, кто сейчас ходит

`Battle.Execute` сразу меняет состояние и возвращает `ActionResult`, а презентация его только проигрывает. Так состояние боя не зависит от анимаций

Последовательность ходов и анимаций сделал на UniTask, анимации на DOTween. Пауза работает через `Time.timeScale`, выход и перезапуск отменяют всё одним токеном

Для зависимостей взял VContainer. На каждый запуск боя создаётся свой дочерний скоуп, при перезапуске он уничтожается целиком, и от прошлого боя ничего не остаётся. Состояния приложения (меню и бой) сделал на UniState. UI сделан на UIKit, это моя библиотека поверх UI Toolkit для имплементации MVVM

## Что осталось и ограничения

Через конфиги настраивается многое, но есть вещи, для которых придётся немного поменять код:

- Новый эффект (яд, бафф, щит и так далее) требует нового значения в `EffectType` и ветки в `BattleRules.Resolve`. Сейчас у способности ровно один эффект и одна сила, поэтому удар с одновременным лечением собрать из конфига нельзя
- То же с правилами выбора цели. Например, "только задний ряд" или "только себя" нужно добавлять в `TargetRule` и в `BattleRules.AvailableTargets`
- Тип анимации не задаётся в конфиге, `BattlePresenter` сам решает по `RequiresFrontline`, будет это рывок к цели или выстрел. Для своей анимации на конкретную способность нужно добавить поле в `AbilityConfig` и обработать его в презентере
- Из меню всегда запускается `DefaultLineup` из `BattleConfig`. Чтобы выбирать бой, нужен экран выбора и передача другого `BattleLineup` в `MenuState`
